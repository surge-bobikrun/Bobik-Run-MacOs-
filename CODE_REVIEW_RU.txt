BOBIK RUN — РЕЗУЛЬТАТ ПОВТОРНОГО ПРОСМОТРА КОДА
================================================
Источник: BobikRun_v1_9_9_FastRounds.zip, распакованы все 46 файлов.
Просмотрены index.html, progression.js, sw.js, manifest.json,
supabase-config.js, config.toml, четыре Edge Functions, README,
заметки аудита и локальные миграции.

ИСПРАВЛЕНО
----------
1. Неограниченный JSON в account-gateway — ограничение 8 КиБ по фактическим
   байтам потока, корректный HTTP 413/400.
2. Неограниченный JSON в admin-panel — ограничение 16 КиБ.
3. Проверка размера тела bobik-run-api считала UTF-16 длину строки, а не байты,
   и могла не учитывать отсутствие Content-Length. Теперь поток ограничен
   16 КиБ по фактическим байтам.
4. Гонка prewarm-сессий: старый запрос мог завершиться после отмены, когда уже
   был запущен новый запрос с тем же ключом режима/сложности, и подменить новую
   подготовленную сессию старой. Добавлен generation token и очистка Promise
   только владельцем этого Promise.
5. Ошибка получения состояния после уже успешной покупки/улучшения теперь не
   превращает подтверждённую транзакцию в HTTP-ошибку. Клиент применяет данные
   результата покупки, если повторная синхронизация состояния тоже недоступна.
6. Админская выдача награды не возвращает 500 после уже успешного начисления,
   если не сохранилось уведомление. Сбой аудита игрового эффекта также выдаёт
   success + warning, не провоцируя повторное применение эффекта.
7. Номер версии приложения и PWA оставлен 1.9.5; изменён cache key SW.

ОБНАРУЖЕННЫЕ ОСТАТОЧНЫЕ РИСКИ / ЧТО НУЖНО ПРОВЕРИТЬ В LIVE
--------------------------------------------------------
- Ограничение тела запроса в исходниках Edge Functions заработает в LIVE только
  после отдельного деплоя соответствующих функций.
- account-gateway доступен до входа и использует service key только на сервере.
  Следует включить/проверить rate limiting на gateway/edge и Supabase Auth
  Leaked Password Protection. Сам файл не подтверждает состояние настроек LIVE.
- account-gateway и admin-panel используют Access-Control-Allow-Origin: *.
  Это допустимо для публичных API при корректной авторизации, но origin allowlist
  уменьшит нежелательные вызовы из браузеров. Publishable key не является секретом.
- bobik-run-api проверяет авторизованного пользователя и передаёт user_id в
  server-only RPC. Реальную устойчивость к накрутке определяют тела SQL RPC,
  действующая схема и ограничения LIVE. Нельзя выводить её только из клиента.
- Админ-поиск делает до 25 параллельных auth.admin.getUserById вызовов; при росте
  нагрузки это может упираться в задержки/лимиты. В дальнейшем лучше читать
  нужные статусы из серверной таблицы/батчевого источника, если он доступен.
- Service Worker применяет network-first к same-origin GET. При ошибке сети
  отдаёт кэш; это обеспечивает офлайн-режим, но кэшированные HTML/конфиг могут
  быть устаревшими до успешного сетевого обновления.
- progression.js присутствует в архиве, но не подключается отдельным script
  тегом в index.html: прогрессия встроена в inline-блок страницы. Файл выглядит
  как отдельная/устаревшая копия; не удалял его, чтобы не ломать внешние ссылки.
- В LIVE применено 62 миграции, а локальный архив содержит только 30 SQL-файлов.
  История LIVE в текстовом файле и локальная папка migrations не совпадают.
  Ни одна SQL-миграция в этой работе не редактировалась и не запускалась.

НЕ ПОДТВЕРЖДЕНО ЭТИМ АУДИТОМ
---------------------------
- Нельзя подтвердить, что текущие Edge Function версии в LIVE соответствуют
  исходникам архива: для этого нужен доступ к развернутому коду/логам Supabase.
- Нельзя подтвердить end-to-end поведение реального Android/PWA или задержки
  без тестового устройства, сети и тестового аккаунта.
- Нельзя подтвердить актуальную структуру LIVE БД по неполному локальному
  набору миграций. Перед любыми SQL-изменениями нужно сверить migration history.

РЕВЬЮ БИЛДА 40 · 2026-11-18
===========================

Исправлено: публичный подробный Realtime broadcast; UUID в presence payload; необрезанные тела HTTP-запросов в трёх функциях; ложный HTTP-отказ после успешной серверной покупки при ошибке отдельного refresh; HTML-инъекция через сырые тексты исключений системы наград; нечитабельное сообщение об ошибке Edge Function; наложение логотипа и слогана на низком экране.

Проверено локально: основные переходы меню, магазин (персонажи/машины), профиль, уровни/достижения/задания/охота, запуск и завершение забега, начисления, быстрый повтор и перезапуск из паузы. Пробный вход использовал только локальную заглушку на 127.0.0.1:9 и синтетические значения; реальные данные аккаунта не отправлялись.

Непокрыто: настоящий вход владельца и другого пользователя, авторизованные действия admin-panel, полный онлайн-цикл покупок/таблиц/хантов, реальное мобильное устройство, стресс/anti-cheat тест. Неизвестны интеграция и хостинг статического сайта, поэтому GitHub PR нужно опубликовать отдельно.

REWARD FIX + DESKTOP KEYBINDS · 2026-11-18
==========================================

- Live Postgres logs pinpointed the payout rollback: leaderboard insert triggers
  bobik_reconcile_hunt_leader_holds(), whose first cleanup statement was an
  unfiltered DELETE. The older repair migration used case-sensitive text replacement
  and did not match pg_get_functiondef's uppercase SQL.
- Applied migration 20261118152818_fix_hunt_hold_reward_delete. It performs a
  case-insensitive exact-statement replacement with `WHERE user_id IS NOT NULL`;
  user_id is the NOT NULL primary key. Live function-definition verification shows
  the safe filter and no remaining unfiltered delete in either affected function.
- The finish failure handler no longer aborts a run after a transient error. It keeps
  the exact run ID/result and offers a retry button that only displays server-returned
  rewards; it never estimates coins or XP.
- Desktop settings now remap left/right, pause, replay, and keys for all four modes.
  Bindings are stored locally, duplicate bindings are rejected, and defaults can be
  restored. Arrow/A-D and mobile pointer controls remain available.
- v1.9.5 and Build 40 naming are unchanged. The Service Worker cache key was bumped
  so installed PWAs fetch this patch. Replay continues to consume the prepared server
  run session, launched in parallel with result settlement.

Not verified with a real player session: successful payout after this live migration.
The PostgreSQL failure path is confirmed from prod logs and the live function body
was checked after migration; an end-to-end run requires the owner's active game session.
Дополнение Build 40: политика новой учётной записи и смены пароля синхронизирована с supabase/config.toml — минимум 8 символов, буква и цифра. Вход сохраняет совместимость со старыми паролями от 6 символов.
