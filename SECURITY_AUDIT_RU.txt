ADMIN PANEL — OWNER ONLY
- Edge Function validates the bearer token with `auth.getUser()`.
- It compares the authenticated user's UUID against one hardcoded OWNER_ID before creating a service-role client.
- All admin actions (search, ban/unban, interrupt, broadcast, news management and dashboard) run after that owner check.
- The owner UUID is not embedded in the public browser bundle. The button is shown only after a successful server-side dashboard authorization check; the server check remains the actual security boundary.
- `admin_users` and `user_roles` have no client grants and no RLS policies. The old `bright-processor` endpoint previously allowed role activation using a code hash; it has now been replaced by a minimal endpoint that verifies the JWT and rejects all legacy admin actions. The primary `admin-panel` owner check is authoritative.
- The service/secret key is read only from Edge Function environment variables and is not placed in browser files.

DATABASE ACCESS
- Direct client SELECT/INSERT/UPDATE on `admin_users`, economy, player stats, run sessions and hunt records is denied.
- RLS-enabled internal tables with no policies are intentionally closed; the client roles have no table grants.
- Public read access is limited to intended game data such as news, global messages, public profiles, public progress and run history.
- `online_presence` is scoped to the authenticated user's own row.
- `game_interrupts` allows users to read/acknowledge only their own messages; admin writes are performed server-side.
- Server-only game RPCs retain EXECUTE only for `service_role`.

SECURITY DEFINER FUNCTIONS — REVIEWED
- `bobik_username_available`: public by design; validates input and returns only a boolean.
- `get_bobik_global_hunt_progress`: public by design; returns display name, best distance, percent, completion flag and attempts for the active hunt. It does not return account UUIDs.
- `get_bobik_hunt_completions`: public by design; returns display name, target/actual distance, percentage and timestamp only; no account UUIDs.
- Profile registration/update, access check, code redemption and username rename are callable only by authenticated users and scope writes to `auth.uid()`.
- `get_bobik_hunt_leaderboard` was removed from anon/authenticated EXECUTE because the updated UI no longer needs the UUID-bearing aggregate RPC; service_role retains access.
- All reviewed SECURITY DEFINER functions use an empty `search_path` setting.

ADVISOR RESULTS
- No-policy RLS INFO findings remain on 10 internal tables. Their client grants are false, so they remain inaccessible to anon/authenticated.
- Public SECURITY DEFINER warnings remain for the three intentional public endpoints above. They return only public game/profile information and have fixed search paths.
- Authenticated SECURITY DEFINER warnings remain for self-scoped profile/account RPCs and the public hunt progress function.
- Leaked Password Protection is still disabled in Supabase Auth. Enable it in the Supabase dashboard if the current plan exposes the setting.
- Performance INFO findings concern 23 tables in the historical `bobik_backup_20261115` schema and 4 indexes not yet used. No live index was removed without evidence.
- Health advisor returned no findings.

LIMITATIONS
- Client-reported distance is still validated for plausible elapsed time/distance but is not equivalent to server-side physics simulation.
- Full browser/mobile penetration testing and real-device E2E were not performed in this environment.
- No security system can guarantee protection against every attack.


ДОПОЛНЕНИЕ 2026-11-16 — АДМИН-ПАНЕЛЬ И ТЕЛЕМЕТРИЯ
- Edge Function admin-panel развернута как version 10 (ACTIVE), verify_jwt=true. До любого действия вызывает auth.getUser() и сравнивает user.id с фиксированным OWNER_ID аккаунта surge.
- Service-role/secret key читается только из Edge Function environment; ключ не передаётся в HTML, JS или GitHub.
- Админская выдача наград выполняется серверной RPC admin_grant_rewards, закрытой от anon/authenticated и доступной только service_role; actor ID и actor username дополнительно сверяются в RPC. Действия пишутся в admin_action_audit.
- Игровое наблюдение ограничено телеметрией: статус забега, режим, дистанция, скорость, ID персонажа/машины и время последнего обновления. Запись экрана, камеры или микрофона не осуществляется.
- Эффекты slow/boost/manual/bobik/clear ограничены 5–300 секундами и сопровождаются уведомлением с именем surge; изменения записываются в журнал. Клиент не имеет права изменять game_player_controls.
- Таблицы game_live_state и game_player_controls имеют RLS; пользователь может публиковать/читать только свою телеметрию и читать только собственную команду. admin_player_notices доступна пользователю только для чтения своих уведомлений и отметки их прочитанными.
- The Rook: титул «Формула 1», стиль rook_green назначен сервером. Защита не позволяет пользователю самостоятельно менять is_creator/custom_title/title_style.
- Ограничение: телеметрия поступает от клиентской игры и сама по себе не является античитом; игрок может подделать собственные поля скорости/модели. Админ-панель показывает последнее значение и статус свежести, но не скрытое изображение экрана.
- Остаточные предупреждения Supabase: leaked-password protection отключена; несколько SECURITY DEFINER RPC доступны авторизованным пользователям и требуют ручного просмотра логики перед изменением прав.


ПРОВЕРКА LIVE SUPABASE 2026-11-16
- Подтверждена одна запись bobik_global_hunt_state (id=1), активное задание «БЕГИ» / 👁️ / 3000 м / Кошмар.
- RPC get_bobik_global_hunt_progress возвращает user_id, display_name, прогресс, выполненность и hold_seconds; EXECUTE доступен только authenticated. RPC get_bobik_hunt_completions возвращает user_id для ссылок на профиль; EXECUTE доступен только authenticated.
- Прогресс RPC проверен прямым smoke-test: вызов завершается без ошибки. Для только что сменившейся цели отсутствие строк означает отсутствие забегов по новой цели, а не ошибку RPC. История завершений содержит прежние записи.
- Владелец surge имеет is_creator=true. The Rook имеет custom_title=«Формула 1», title_style=rook_green.
- Владелец админ-панели проверяется по фиксированному UUID на серверной Edge Function. admin_grant_rewards имеет EXECUTE только service_role. Таблицы админского журнала/команд/уведомлений закрыты RLS и grants согласно модели self-read/service-only.
- 12 таблиц с RLS без пользовательских политик — закрытые служебные таблицы; это deny-all для anon/authenticated, не открытый доступ.
- SECURITY DEFINER функции профиля/регистрации используют auth.uid() и обновляют только собственную строку; username_available возвращает только boolean и оставлен публичным для проверки имени при регистрации. Публичные hunt RPC отдают только игровую статистику, имя и публичный UUID профиля.
- Остаточный пункт: Supabase Auth Leaked Password Protection выключен. Его нужно включить вручную в Dashboard → Authentication → Security/Password Protection; API-инструмент текущей сессии не предоставляет изменения этого Auth-настройки.
- Ограничение телеметрии: значения публикуются клиентом игрока и могут быть им подделаны; это наблюдение за текущим состоянием, а не серверный античит.

- Глобальная серия из пяти заданий продвигается только сервером; финальное удержание топ-1 проверяется по 10 категориям таблицы лидеров, а таймер сбрасывается при потере первого места.

КОРРЕКЦИЯ АУДИТА · БИЛД 40 · 2026-11-18
========================================

В предыдущей записи аудита было неполное описание наблюдения: в клиенте присутствовал открытый Realtime broadcast-канал bobik-live-round с игровыми кадрами, UUID игрока, точной внутриигровой позицией и списками препятствий/объектов. Это не была запись экрана, но подписчик публичного канала мог получать опубликованные кадры. Предыдущую формулировку о телеметрии только из статуса/скорости считать устаревшей.

В Билде 40 клиент больше не публикует кадры в этот открытый канал; серверный admin-panel выдаёт снимки только после проверки JWT и фиксированного UUID владельца. Клиентские строки присутствия теперь не содержат аккаунтный UUID. Пользовательский текст профиля прямо описывает положение, транспорт, препятствия и частоту снимков, а также отсутствие доступа к камере, микрофону и записи экрана.

Функции LIVE обновлены:
- account-gateway v2 (verify_jwt=false сохраняется только для входа до авторизации; API-ключ проверяется на сервере; тело ограничено 8 КиБ);
- admin-panel v15 (verify_jwt=true, проверка владельца до service-role операций; тело ограничено 16 КиБ);
- bobik-run-api v9 (verify_jwt=true и проверка пользователя; тело ограничено 16 КиБ по фактическим байтам).

Миграции не выполнялись. Удалён неподходящий файл 20261118140000_bobik_username_tags_and_live_spectator.sql: его код синхронизации никнейма не включал все таблицы, которые обслуживает текущий LIVE-триггер. Схему и применённую историю миграций не меняли.

ОСТАТКИ, ТРЕБУЮЩИЕ РУЧНОГО ДЕЙСТВИЯ
- Supabase Dashboard → Realtime → Settings → выключить “Allow public access”. Иначе старые версии клиента всё ещё могут подключаться к публичным каналам до обновления сайта.
- Supabase Dashboard → Authentication → Security → включить Leaked Password Protection, если пункт доступен в тарифе.
- Исходники сайта находятся в отдельном GitHub PR; PR не слит и статический сайт не опубликован. Пока новая версия не опубликована, точка входа в GitHub/сайт может обслуживать старый JS и старый Realtime-канал.

Ограничения: системный флаг Realtime и защита слабых/утёкших паролей не доступны через подключённые API-инструменты. В этом окружении не проводились тестирование с реальной учётной записью, нагрузочный тест, атака с чужого аккаунта или проверка на устройстве Android/iOS. Клиентские игровые координаты остаются заявленными клиентом и не являются античитом.

ДОПОЛНЕНИЕ · ПОВТОРНЫЙ ПРОСМОТР КЛАВИШ И НАГРАД · 2026-11-18

- Сохранённые назначенные клавиши теперь валидируются по допустимым кодам; произвольная строка из localStorage не вставляется в DOM. Запрещены F5, F11 и F12, чтобы переназначение не ломало обновление/полноэкранный режим/инструменты браузера.
