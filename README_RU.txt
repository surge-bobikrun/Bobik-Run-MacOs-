BOBIK RUN v1.7.8 — SUPABASE CONFIG FIX

Что добавлено
- Регистрация и вход через Supabase Auth (имя игрока + пароль; внутренний адрес создаётся автоматически).
- Автосохранение игрового прогресса в таблицу game_saves; у каждого аккаунта своё сохранение.
- Глобальная таблица лидеров по 3 режимам и 3 сложностям. У таблицы есть боковая стрелка «назад».
- Промокоды: bobiksecret — 100 монет; freeartemus — 300 монет; bananus — открывает и выбирает машину «Банан». Каждый код можно использовать один раз на аккаунт.
- Админ-панель открывается вводом специального серверного кода в разделе промокодов. Кнопки админ-панели в настройках нет. Список аккаунтов и блокировка на 24 часа работают через защищённую Edge Function.
- Админ-код проверяется на сервере; его значение не хранится в HTML/JavaScript.

ВАЖНО: что нужно включить в Supabase один раз
Эта папка содержит клиентский код, SQL-миграцию и Edge Function. Само приложение не может самостоятельно применять SQL или публиковать серверные функции в твой Supabase-проект. Перед публикацией выполни шаги ниже.

1) Применить базу данных
- Открой Supabase Dashboard своего проекта.
- Перейди в SQL Editor → New query.
- Открой файл supabase/migrations/202611120001_bobik_cloud.sql, скопируй весь текст и выполни его.
- В результате появятся profiles, game_saves, leaderboard, promo_redemptions и user_roles, RLS-политики и две SQL-функции.

2) Проверить Auth
- В Authentication → Providers → Email включи Email provider.
- При включённом Confirm email пользователю нужно подтвердить почту по письму перед входом. Для теста можно временно выключить Confirm email.
- Не отключай защиту паролей и не публикуй чужие пользовательские данные.

3) Развернуть админ-функцию
Нужен Supabase CLI и вход в свой Supabase аккаунт. Из корня этой папки выполни:

  npx supabase login
  npx supabase link --project-ref nrmfygckxovwkkhvsywe
  npx supabase secrets set ADMIN_PANEL_CODE="ВСТАВЬ_СЮДА_СВОЙ_КОД_АДМИНКИ"
  npx supabase functions deploy admin-panel

Вместо текста ВСТАВЬ_СЮДА_СВОЙ_КОД_АДМИНКИ укажи тот секретный код, который должен открывать админ-панель. Не добавляй его в index.html, supabase-config.js или GitHub.

4) Проверить конфигурацию приложения
- В supabase-config.js уже записаны URL и publishable key из исходного архива. Проверь, что это именно твой Supabase-проект и ключ актуален.
- В браузере разрешён только publishable key. Никогда не вставляй сюда secret/service_role key.
- В Supabase оставь включённым Row Level Security: SQL-миграция включает RLS для всех таблиц.

5) Опубликовать игру
Загрузи содержимое папки BobikRun_v1_7_6_SUPABASE в корень GitHub Pages/хостинга. Убедись, что вместе с index.html опубликованы supabase-config.js, manifest.json, sw.js и папка supabase (папка supabase нужна для CLI-развёртывания, она может храниться в репозитории). После публикации открой игру заново или очисти кеш PWA.

Проверка после настройки
1. Создай аккаунт с почтой и паролем, выйди и войди снова.
2. Запусти заезд, заработай монеты/рекорд, обнови страницу и проверь, что прогресс вернулся.
3. Открой игру в другом браузере/устройстве и войди тем же аккаунтом — должно загрузиться то же сохранение.
4. Открой «Таблицу лидеров» и проверь рекорды.
5. В «Настройки → Промокоды» проверь все три награды и повторное использование кода.
6. Введи серверный админ-код, откроется админ-панель. Проверь блокировку тестового аккаунта и снятие блокировки.

Примечания
- Старые локальные аккаунты из версии 1.7.5 не превращаются автоматически в Supabase-аккаунты: зарегистрируй облачный аккаунт. Текущий локальный прогресс на устройстве используется как начальное сохранение, если в новом облачном аккаунте ещё нет game_saves.
- Результаты лидерборда отправляются клиентом игры, поэтому, как и у большинства браузерных игр без серверной симуляции, технически продвинутый пользователь может подделать свой результат. RLS не позволяет менять записи других аккаунтов.
- Блокировка аккаунтов защищена серверным ключом и выполняется Supabase Auth Admin API; service/secret key не попадает в браузер.


Дополнительная правка:
- Исходник функции admin-panel синхронизирован с развёрнутой версией: секретный код проверяется по SHA-256 хешу из закрытой таблицы bobik_private_config, а не хранится в клиентском файле или открытой переменной.
- Добавлена миграция 202611120002_security_hardening.sql. Она ограничивает вызов функции активации промокодов авторизованными аккаунтами и закрывает таблицы ролей/истории промокодов.


ИЗМЕНЕНИЯ В ВЕРСИИ USERNAME_FIX:
- Поле почты убрано из интерфейса: вход и регистрация выполняются по имени игрока и паролю.
- Для Supabase Auth имя преобразуется в стабильный внутренний адрес вида u<hash>@accounts.example.com. Почта игрока не запрашивается.
- Старые аккаунты, созданные с реальной почтой, пока могут войти, введя старую почту вместо имени игрока.
- Добавлен резервный источник загрузки Supabase JS SDK (unpkg), если основной CDN недоступен.
- Обновлён ключ кэша Service Worker, чтобы браузер загрузил новую версию файлов.

ВАЖНАЯ НАСТРОЙКА SUPABASE:
Чтобы новые аккаунты сразу получали сессию без письма, открой настройки Authentication -> Providers -> Email и выключи Confirm email. Иначе Supabase создаст пользователя, но не выдаст сессию до подтверждения внутреннего адреса.
