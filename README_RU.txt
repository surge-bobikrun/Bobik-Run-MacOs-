BOBIK RUN v1.9.5 — ИСПРАВЛЕНИЯ НАДЁЖНОСТИ И БЫСТРОГО ПОВТОРА
============================================================

Версия приложения намеренно оставлена 1.9.5.
Основа — архив Bobik Run v1.9.9 FastRounds, предоставленный в этой переписке.

ИСПРАВЛЕНИЯ В ЭТОЙ СБОРКЕ
-------------------------
1. Защита от больших HTTP-тел запросов
- account-gateway: JSON-тело ограничено 8 КиБ; размер проверяется по байтам,
  в том числе при отсутствии/подделке Content-Length. Слишком большой запрос
  получает HTTP 413, некорректный JSON — HTTP 400.
- admin-panel: JSON-тело ограничено 16 КиБ тем же потоковым способом.
- bobik-run-api: заменена проверка длины JS-строки на потоковое ограничение
  фактического размера тела в байтах (16 КиБ).

2. Исправлена гонка предварительной подготовки забега
- Каждая подготовка получает номер поколения.
- Отменённый или заменённый запрос больше не может перезаписать новую сессию,
  даже если следующий запрос использует тот же режим и сложность.
- Завершение старого запроса очищает только собственный Promise, не сбрасывая
  ссылку на более новый запрос.

3. Версия и PWA
- Версия в заголовке страницы, manifest, меню и истории изменений — 1.9.5.
- Ключ Service Worker изменён, чтобы клиенты получили обновлённые файлы.

ВАЖНО О LIVE SUPABASE
---------------------
- SQL-миграции не изменялись и не добавлялись.
- В этом архиве содержится 30 локальных SQL-файлов; в LIVE применено 62 миграции.
  Локальная история неполная и не является зеркалом LIVE.
- Не запускать SQL-файлы архива повторно и не считать их полной схемой LIVE.
- Изменены исходники Edge Functions. Если они используются в LIVE, их нужно
  развернуть отдельно после проверки окружения. Публикация только статических
  файлов сайта не обновит серверные ограничения размера тела.

ПРОВЕРКИ
--------
- JavaScript-блоки index.html, progression.js, supabase-config.js и sw.js
  проходят node --check.
- TypeScript исходники Edge Functions проверены компилятором на синтаксис;
  разрешение npm:-импорта Supabase зависит от Deno Deploy и не проверяется Node.
- Проверена целостность итогового ZIP.
- Полный end-to-end тест с LIVE Supabase и Android в этой среде не выполнялся.

ОГРАНИЧЕНИЯ АУДИТА
-----------------
- Веб-клиентская телеметрия не является доказательством физического движения.
  Серверная проверка результата остаётся ограниченной данными и правилами,
  которые реализованы в LIVE RPC; для строгого античита нужна серверная
  симуляция/валидация траектории.
- account-gateway по-прежнему использует широкую CORS-политику и публичный
  publishable key — это не секрет. Нужны ограничения частоты запросов на
  инфраструктурном уровне и включённая защита от скомпрометированных паролей
  в Supabase Auth.
- Клиентские HTML/JS-файлы содержат большой игровой модуль. Статическая
  проверка синтаксиса не заменяет прохождение всех экранов и игровых сценариев.

ОБНОВЛЕНИЕ БИЛД 40 · v1.9.5
===========================

Название и версия приложения остались v1.9.5. Номер билда показан в главном меню; ключ Service Worker обновлён для установки файлов билда 40.

ИСПРАВЛЕНИЯ
- Ошибка Edge Function при входе теперь показывается коротким сообщением по-русски; пароль и сырое сетевое исключение в интерфейс не выводятся.
- Ответы об ошибке наград проходят HTML-экранирование.
- Заменена открытая Realtime-трансляция кадрами раунда на серверное наблюдение владельца через admin-panel и снимки около одного раза в секунду.
- Присутствие в публичном Realtime канале содержит случайный ключ вкладки и отметку времени, без UUID аккаунта; счётчик подписан как число активных вкладок.
- Для запросов account-gateway (8 КиБ), admin-panel (16 КиБ) и bobik-run-api (16 КиБ) действует потоковый лимит фактических байтов. Успешная покупка/смена выбора/улучшение не превращается в ошибку, если не удалось обновить снимок состояния.
- Исправлено наложение логотипа и слогана на низком экране; стеклянные панели получили более чёткий контур и контраст, заметный клавиатурный фокус и поддержку сниженных анимации/прозрачности.

БАЗА ДАННЫХ И ПУБЛИКАЦИЯ
- SQL-миграция не требуется: используем существующий game_live_state.live_frame и действующий owner-only admin-panel.
- Удалён неподходящий локальный migration-файл 20261118140000_bobik_username_tags_and_live_spectator.sql: его реализация триггера отставала от LIVE и могла отключить часть уже работающей синхронизации зеркал. Не запускай старые файлы migrations из этого архива в LIVE.
- Локальный preview, используемый для тестов входа, отдельно направлен на 127.0.0.1:9. Эта тестовая подмена отсутствует в приложении и supabase-config.js этого архива.
- Для обновления сайта требуется опубликовать исходники из GitHub PR. Старые клиенты могут продолжать использовать старый публичный Realtime канал до обновления сайта/перезагрузки.
- В Supabase Dashboard вручную выключи Realtime → Settings → Allow public access. В текущем наборе Supabase-инструментов нет операции для этого системного переключателя.
- Включи Leaked Password Protection в Authentication → Security, если настройка доступна на плане проекта.

ПРОВЕРКИ
- Семь встроенных JavaScript-блоков, progression.js, supabase-config.js и sw.js прошли node --check; JSON-файлы разобраны без ошибки.
- Локально проверены вход с синтетическим тестовым аккаунтом (получен ожидаемый общий отказ 401), потоковый предел account-gateway (413), запуск/завершение забега, начисление локальных монет и XP, быстрый повтор, перезапуск из паузы, профиль, магазин, достижения, задания и глобальная охота.
- Реальный вход игрока, учётная запись владельца и платформа публикации сайта в плейтест не использовались.
Дополнение Build 40: политика новой учётной записи и смены пароля синхронизирована с supabase/config.toml — минимум 8 символов, буква и цифра. Вход сохраняет совместимость со старыми паролями от 6 символов.
